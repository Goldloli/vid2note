Ingest 闭环与推荐技术栈

首版只证明一件事：加入第二个视频后，既有 Wiki 页面被可靠地增强，而不是多出第二篇孤立摘要。

一次完整 Ingest
1

来源固化

下载视频、计算哈希、生成 source_id、保存 SRT 与带时间锚点逐字稿。

2

来源笔记

按章节整理 Markdown；每个核心判断绑定一个或多个 SRT 时间区间。

3

关联发现

先读 index.md，再用文件名、双链、FTS5 找相关 Wiki 页面；首版不需要向量库。

4

变更提案

LLM 输出结构化 ChangeSet：新增、补充、替换、矛盾、引用，不直接写文件。

5

人工审批

Merge View 展示前后差异；可逐页、逐块接受或拒绝，并给 Agent 反馈。

6

原子落盘

校验链接与引用后写入，更新 index/log，创建版本快照并刷新搜索索引。

保留并强化

桌面：Electron + Vue 3 + Pinia + Vite

服务：Python 3.11 + FastAPI + Pydantic v2

媒体：FFmpeg + 现有下载器 / ASR 适配层

任务：asyncio worker，但改为真正并发、可恢复的 Job 模型

实时：SSE 继续用于任务和 Agent 事件流

新增但保持轻量

Markdown：markdown-it-py + YAML frontmatter

搜索：SQLite FTS5 + index.md；后期可插拔 qmd / 向量检索

编辑与审批：CodeMirror 6 + Merge View

文件监听：watchfiles，兼容用户在 Obsidian 外部修改

版本：内部 ChangeSet 快照；可选 Git 自动提交

Agent Runtime

内置 Agent：自研薄状态机 + Pydantic 结构化输出 + Provider Adapter。流程固定为定位 → 阅读 → 回查来源 → 回答 → 可选提交 ChangeSet。

外部 Agent：Codex / Claude Code Adapter 在临时 Vault 副本中运行，通过文件 Diff 转为同一种 ChangeSet；绝不直接放任外部进程改正式 Wiki。

MCP：后期把搜索、读取页面、取逐字稿、生成媒体片段暴露成统一工具协议；它是适配边界，不是首版前置条件。

首版要有

  • 两视频合并到同一 Wiki 页面
  • 逐项审批与撤销
  • 来源 + 时间码引用
  • Agent 先读 Wiki 再回答
  • 按需截图和视频片段

明确延后

  • 全格式文件自动摄取
  • 知识图谱数据库
  • 多 Agent 协作
  • 云同步与多人协作
  • 预生成全部媒体切片
