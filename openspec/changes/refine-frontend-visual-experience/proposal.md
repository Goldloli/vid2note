## Why

设置与 ASR 页面已经形成清晰的「页面标题、页内导航、分区内容、状态反馈」层级，但主控台、笔记、思维导图和历史仍沿用较早的通用卡片拼装，导致六个主页面在信息密度、空间节奏、交互反馈和窄屏表现上明显割裂。现在需要以设置与 ASR 为质量基线完成一次全局精修，让本地生产力工具在保持克制、高效的前提下拥有统一且更成熟的视觉体验。

## What Changes

- 统一应用骨架：优化顶部标题栏、左侧导航、图标、激活态、引擎状态与主内容区宽度规则，保留六个全局入口和现有路由。
- 建立可复用的页面层级与状态组件，包括页面头、分区标题、指标卡、工具栏、空状态、加载骨架、状态反馈和自适应工作区。
- 重构主控台的信息优先级：突出任务创建，收纳高级参数，强化运行任务状态，并将统计与最近完成内容整理为更易扫描的层级。
- 主控台的 LLM 选择 MUST 以后台设置响应为准，只展示已完成必需配置的厂商；未配置凭证或缺少必需模型/地址的厂商不得进入任务级下拉选项。
- 将笔记与思维导图升级为统一的资料库工作区：可搜索资料列表、主要阅读/画布区、可折叠上下文侧栏以及沉浸式查看能力。
- 修复笔记正文与章节大纲的渲染时序，确保资料库页和单篇笔记页在正文标题挂载后生成可导航大纲。
- 精修历史页的筛选、批量操作、状态表达和分页；桌面使用数据表格，平板/窄窗口使用更适合阅读与操作的自适应布局。
- 让设置与 ASR 页面接入相同的页面头、间距、状态和响应式规则，在保留其现有信息架构的同时消除局部风格漂移。
- 保留亮色、暗色和装饰背景选项，但降低背景干扰；统一 focus、hover、loading、empty、error 和 reduced-motion 行为。
- 覆盖桌面与平板/小窗口场景，确保导航、三栏工作区、表格、工具栏和页签在窄屏下不会溢出或遮挡关键操作。
- 不改变后端接口、任务流水线、ASR/LLM 配置语义、产物格式或持久化模型。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `web-frontend`: 补充统一视觉层级、资料库工作区、自适应导航与内容布局、跨页面状态反馈和可访问性要求。

## Impact

- 主要影响 `frontend/src/App.vue`、`frontend/src/styles/app.css`、六个主页面及其共享 Vue 组件。
- 可能调整前端本地状态和路由查询参数以保存选中项或面板状态；LLM 可选项复用现有 `/api/v1/settings` 中的 provider、profile 与凭证状态，不新增或修改后端 API。
- 继续复用 ai_srt2md fork 中已有的任务、笔记、导图、配置和导出能力；本变更只新增/改造 Vue 前端的呈现与交互编排，不穿透或重写后端内核。
- 前端依赖以现有 Vue 3 技术栈为主；图标使用单一的 Phosphor Vue 图标家族并通过本地依赖打包，不引入远程资源。

## Non-goals

- 不重做后端、任务 DAG、ASR、LLM、数据库或 Docker 部署架构。
- 不增加登录、多用户、远程同步、Electron 客户端或手机优先体验。
- 不增加思维导图编辑、笔记协作、富文本编辑等新的产品能力。
- 不用玻璃拟态、渐变背景、hover scale 或高干扰动效替代现有的清晰克制设计原则。
