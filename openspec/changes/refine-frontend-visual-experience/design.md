## Context

当前前端由 Vue 3、Vue Router、Pinia 和一份全局 `app.css` 组成。`App.vue` 提供 48px 顶栏、220px 左侧栏和主滚动区；设置与 ASR 页面已经通过页面头、页签、分区容器、字段组件、状态徽章和 Toast 建立了较完整的界面层级，而主控台、笔记浏览、思维导图浏览和历史仍主要依赖早期的 `.card`、`.spread`、`.table` 等通用类，视觉密度与交互反馈不一致。

本次变更面向个人本地 Docker Web 应用，现有路由、后端 API、任务模型、导出能力和配置语义均是稳定边界。用户选择的方向是：以设置/ASR 为基准再精修一档，信息密度适中，允许优化导航和纯前端交互，覆盖桌面及平板/小窗口，视觉方案由实现侧统一把控。

## Goals / Non-Goals

**Goals:**

- 让六个主页面共享同一套页面层级、间距、色彩、状态反馈和交互语言。
- 在不牺牲效率的前提下提升视觉完成度，形成清晰、克制的本地生产力工具气质。
- 将笔记和思维导图整理为可复用的资料库工作区模式。
- 让应用骨架、工作区、表格、工具栏和页签在桌面与 768px 以上的小窗口/平板环境中可用。
- 保持亮暗主题、键盘焦点、减少动态效果偏好和现有中英文能力。
- 不改变后端契约，避免视觉重构与任务处理内核耦合。

**Non-Goals:**

- 不实现手机优先布局，不承诺 768px 以下的完整功能体验。
- 不增加思维导图编辑、笔记编辑、在线协作或新的任务能力。
- 不引入玻璃拟态、渐变背景、hover scale、持续大幅动效等高干扰表现。
- 不重写设置/ASR 的数据管理逻辑，不调整 ai_srt2md fork 内核。

## Decisions

### D1：采用“安静的工作台”视觉语言

继续使用中性灰白/深灰表面、蓝色强调色和实色状态色，强化字号层级、分区边界、留白与对齐。圆角以 8–14px 为主，阴影只表达层级，不制作悬浮玻璃效果；装饰点阵/网格保留为可选背景，但降低对比度并避免穿透主要工作表面。

选择该方向是因为它与用户认可的设置/ASR 页面一致，也符合 `DESIGN.md` 的清晰普通版约束。没有采用大面积渐变或高饱和品牌化方案，因为内容阅读与长时间使用优先。

### D2：应用骨架采用三档自适应布局

- 宽桌面（≥ 1180px）：展示完整侧栏、文字导航、引擎状态和宽内容区。
- 小桌面/横向平板（900–1179px）：侧栏压缩为图标轨道，导航通过可访问名称/提示保持可识别；宽工作区收起次要侧栏。
- 纵向平板（768–899px）：使用紧凑顶栏与可展开导航面板，主内容单列；关键操作保持在页面头或底部操作条中。

页面容器分为标准内容宽度与工作区宽度两类。设置、ASR、主控台和历史使用标准/宽内容容器；笔记与思维导图使用占满可用区域的工作区容器。

没有只缩小固定 220px 侧栏，因为这会在 768–1024px 环境中持续挤压主内容；也不移除左侧导航，因为现有信息架构稳定且用户明确同意“优化而非改路由”。

### D3：建立少量语义化共享原语

新增或提取以下轻量组件/样式原语：

- `AppIcon`：对 `@phosphor-icons/vue` 的轻量语义封装，统一图标家族、尺寸、粗细和可访问名称，避免手绘 SVG 与远程资源。
- `PageHeader`：页面标题、副标题、辅助信息和操作区。
- `SectionHeader`：分区标题、计数和局部动作。
- `EmptyState` / `LoadingState`：统一空、加载、失败表达。
- `LibrarySidebar`：笔记与导图共享的搜索、任务列表和选中态。

设置已有的 `SettingsTabs`、`StatusBadge`、`ToastStack` 等组件继续复用并调整 token，不创建第二套等价组件。通用的排版、表面、按钮、输入、表格和响应式规则仍集中在 `app.css`，页面特有网格留在各自 scoped style。

选择少量组件而不是将每张卡片都组件化，是为了降低重构风险和模板跳转成本，同时避免继续复制结构复杂的页面头与状态视图。

### D4：主控台以“创建任务”为视觉主任务

页面头给出当前服务和默认引擎的轻量上下文；新建任务区位于首屏最突出位置，网络来源与本地来源保持同等入口。ASR、LLM 和输出语言作为常用参数直接可见，详细程度、截图、PDF 等次要参数收进可展开的高级区，但提交值和默认值逻辑保持不变。

任务级 LLM 选项不再使用前端静态厂商全集，而是从现有设置响应的 `providers`、`profiles` 与 `credentials` 派生：远程厂商必须满足注册表声明的必需凭证，要求模型或 Base URL 的兼容服务必须同时具备对应 profile 字段；无凭证字段的本地厂商按完整 profile 视为已配置。当前默认厂商若不可用，则回落到第一个已配置厂商；没有可用厂商时禁用任务提交并引导用户前往设置。该判断只消费布尔配置状态，不读取或回显凭证明文。

统计卡缩小为易扫描的概览带；进行中任务在存在数据时优先于最近完成，保留流水线轨道、进度和详情入口；无运行任务时使用带下一步提示的空状态，避免大片无意义留白。

### D5：笔记与思维导图共享资料库工作区

两页统一使用以下结构：

```
资料列表（搜索/选中态） → 主阅读或画布 → 上下文大纲/导出操作
```

宽屏三栏并列；小桌面收起右侧上下文区，通过页签或切换按钮显示；平板将资料列表变为可展开面板，主内容保持优先。当前选中任务继续使用既有路由查询参数，进入页面默认选择最新完成任务；笔记详情路由和导图详情路由继续可直接打开。

笔记主区强调阅读宽度、标题层级和工具栏；PDF 对照开启时重新分配主区，不额外叠加第三栏。导图主区让画布和视图控制占据最大空间，文本大纲与导出操作集中在上下文栏。

笔记大纲必须在加载骨架退出、净化后的 Markdown 正文实际挂载后再扫描标题，并覆盖渲染层级移位后的 `h2` 至 `h4`。资料切换、请求失败和正文为空时必须清理旧观察器与旧大纲，避免残留上一条笔记的章节；资料库页和单篇详情页采用同一时序约束。

没有把笔记和导图合并为单一路由，因为两个全局入口和用户心智已经稳定；只共享信息架构与组件。

### D6：历史页保持数据表格，并增加自适应表达

桌面继续使用表格以保证扫描效率，将筛选器整理为独立工具栏，批量操作仅在选中行后显示为明确的操作条。状态、来源、时间与产物动作使用统一视觉层级。窄屏下改为任务卡片列表，保留选择、状态、来源、时间、产物和重跑，不依赖横向滚动完成主要操作。

### D7：所有异步页面使用一致的状态模型

首次加载显示与最终布局相近的骨架；无数据时显示说明、下一步和可选主动作；请求失败显示内联错误与重试入口；保存、测试和短操作优先使用 Toast，破坏性或批量动作使用明确确认。不得仅用空白区域表达加载或失败。

本次只改前端反馈，不改变 API 错误格式。页面仍可在必要时使用现有异常信息作为详情。

### D8：可访问性与动态效果是设计系统的一部分

图标按钮必须具备可访问名称，侧栏压缩后不能只靠图形传达；键盘 focus 使用统一 ring；激活状态除颜色外还使用形状/边框/文字；交互目标保持足够尺寸。过渡集中在 120–220ms 的颜色、透明度和位移，`prefers-reduced-motion: reduce` 下关闭非必要动画。

### D9：不新增后端与远程视觉依赖

所有现有 API 调用、Pinia store 和路由保持兼容。Phosphor 图标作为前端构建依赖本地打包，装饰图形使用 CSS 或已有品牌资源，避免 CDN、远程字体和运行时网络依赖。若需要共享状态，仅使用组件状态、现有 store 或路由查询参数。

## Risks / Trade-offs

- [现有工作区已有大量未提交改动，视觉重构可能与前序功能交叉] → 只编辑明确的前端与 OpenSpec 文件，实施前逐文件核对当前内容，不回退未知改动。
- [三档响应式布局会显著增加 CSS 组合复杂度] → 先建立应用骨架和容器规则，再逐页适配；使用少量明确断点和共享变量，避免页面各自定义不同断点。
- [资料库三栏在窄屏下容易隐藏关键操作] → 主内容始终优先，列表和上下文区都提供显式切换入口，并在 768、1024、1280 三个宽度做视觉验收。
- [全局 CSS 改动可能影响任务详情等非六个主页面] → 保持通用类向后兼容，新增语义类逐步迁移；浏览器验收包含任务详情和单篇笔记/导图路由。
- [装饰背景可能降低可读性或暗色主题对比] → 背景仅出现在主内容底层，所有重要内容使用不透明表面，并分别检查亮暗主题。
- [纯视觉工作容易引入功能回归] → 保留现有事件处理和 API 调用，重构以模板结构和样式为主，使用 lint/build、相关测试及关键路径手工验收。
- [加载状态通过 `v-if` 替换正文时，过早扫描 DOM 会得到空大纲] → 先结束加载状态并等待 `nextTick`，再建立标题列表与观察器；浏览器验收必须断言真实笔记的大纲非空。
- [静态 LLM 厂商列表可能允许用户选择缺少凭证的 provider] → 由设置响应中的公开元数据和凭证布尔状态统一派生任务级可选项，并覆盖默认 provider 不可用和零可用项场景。

## Migration Plan

1. 先扩展 token、应用骨架、共享图标和页面状态组件，保持原页面可运行。
2. 依次迁移主控台、笔记资料库、思维导图资料库、历史，再回头统一设置、ASR 和任务详情的局部样式。
3. 每迁移一页即检查现有数据加载、操作入口和空/错/加载状态。
4. 完成全部页面后更新 `DESIGN.md`，运行前端质量门禁和多宽度、双主题视觉验收。
5. 若出现不可接受回归，可按页面回退新增模板/样式；后端和数据无需迁移。
