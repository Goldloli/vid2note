## Why

现有 `concise`、`balanced`、`detailed` 主要依靠同一条 ai_srt2md 单次生成主干叠加少量提示词区分，长视频下缺少可验证的全局覆盖、证据分配和质量审计，也无法稳定形成可度量的深度与成本阶梯；已验证的 `exhaustive` 则采用证据提取、全局蓝图、分章写作和按需修复，质量控制明显更强。现在需要把超详细链路的有效原则抽成共享能力，同时避免让低档位承担超详细的完整调用成本。

## What Changes

- 在任何实现改动前，以三段约 150 分钟视频分别完成简洁、适中、详细真实基线，固定任务 ID、素材时长、ASR 与笔记节点耗时、逐次 usage、费用和笔记产物。
- 将简洁、适中、详细从“通用生成主干 + 提示词差异”改为“内容地图 → 档位证据选择 → 蓝图 → 分章写作 → 确定性门禁 → 按策略审计/修复”的分层流水线。
- 引入统一、可测试的档位策略：简洁只选择关键证据，适中覆盖主要证据并保留代表性解释，详细覆盖全部关键/高价值证据及大部分补充证据；超详细继续覆盖全部非噪声证据。
- 低档位使用轻量全局内容地图，详细档使用压缩证据扩展；复用超详细的事实忠实、全局规划、局部修复原则，但不复制其完整成本。
- 为三档定义不同的章节、证据、示例、审计和调用预算；成本目标作为基准验收指标，不作为生成失败的硬阈值。
- 使用另外三段与基线一一对应、时长差不超过 1% 的长视频复测，记录质量、Token、费用和耗时，并执行后端全量测试与前端构建。
- 为相同输入的内容理解产物预留基于内容哈希和版本的复用边界；本次优先实现任务内复用，不扩展为跨任务持久化缓存。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `note-generation`: 三种非超详细档位改为证据优先的分层生成流水线，并增加可量化的覆盖、成本、审计与真实基准验收要求。

## Impact

- 主要影响 `backend/src/core/simple_processor.py`、`backend/src/prompts/detail_level.py` 及笔记详细程度相关测试。
- 继续通过现有 `BaseLLM` 门面和 usage callback 统计 DeepSeek 缓存命中、未命中与输出 Token；不改变 LLM API、任务创建 API 或历史任务快照字段。
- 复用 ai_srt2md 的字幕解析、提示词安全、Markdown 清洗、PDF 参考和截图处理边界；新增/改造仅限三档笔记的理解、规划、写作与质量控制编排。
- 真实基准会产生六个长视频任务及相应远端 LLM/ASR 使用量。

## Non-goals

- 不修改 `exhaustive` 已验证的主流水线，不恢复已经移除的 `thorough` 档位。
- 不以截断字幕、隐藏 usage、强行限制最终字数或降低输出语言质量换取成本下降。
- 不在本变更中调整 bcut/Whisper 策略、模型供应商、思维导图或前端视觉设计。
- 不承诺不同主题视频之间绝对等价；不同视频用于端到端工程对比，质量判断同时采用归一化指标和人工抽样。
- 不在本次实现跨任务持久化的 Core Map / Evidence 缓存，避免扩大迁移与失效管理范围。
