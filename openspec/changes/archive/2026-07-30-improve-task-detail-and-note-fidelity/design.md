## Goals / Non-Goals

**Goals:**

- 普通用户打开任务详情即可看懂“现在在做什么、已经完成什么、下一步是什么、哪些产物可看”。
- 产物未就绪、404、JSON 错误与 HTML 回退页都有明确空态，绝不作为正文显示。
- 连接后实时事件能显示；中途进入页面也能由节点快照恢复基础活动时间线。
- 历史和新任务的截图均可通过受控的同源产品端点显示。
- `exhaustive` 长字幕的全部有效内容先进入语义证据提取，再由全局蓝图统一课程主线、概念关系、章节结构与证据归属。
- 初稿和最终审校都以全局蓝图与原始证据为依据，消除独立分块造成的重复、割裂和局部视角。
- 为事实忠实度、主题覆盖、结构连贯、信息价值、可读性与各生成阶段留下可测试、可观测的诊断。

**Non-Goals:**

- 不持久化完整逐行日志，不增加日志表或 WebSocket。
- 不自动重写历史笔记，不自动发起会产生费用的真实 LLM 重跑。
- 不用字符比例判定质量，不为了篇幅扩写，不对原始材料做事实补全。
- 不改变非 `exhaustive` 档位的单次生成策略。
- 不改 ASR、PDF 解析、思维导图生成和 LLM provider 适配。

## Decisions

### D1：任务详情使用“权威快照 + 实时增量”的活动模型

页面加载后先把 `task.node_statuses` 转为可读活动项，包括开始、完成、失败与跳过；SSE 连接后再消费 `node-entered`、`node-progress`、`node-product`、`node-completed`、`node-failed`、`log` 和任务终态事件。活动项显示业务名称与用户能理解的描述，技术文件路径和原始 ID 放到“任务参数”中。

选择该方案是因为节点状态已经按 D10 落库，容器重启后仍可信；完整日志当前只存在进程内总线，新增日志表会扩大数据模型和清理范围。替代方案“继续显示黑色终端并等待新日志”无法解决中途进入页面的空白问题。

### D2：产物读取采用“登记门禁 + 响应校验”

前端仅在 `task.srt_path` / `task.note_path` 已登记时请求对应产物。共享读取函数同时校验：

1. HTTP 成功状态；
2. `Content-Type` 不是 `text/html` / `application/json`；
3. 内容开头不是 `<!doctype html>` / `<html>`。

404 表示“尚未生成或已清理”，渲染明确空态；其他异常提供重试。这样即使静态 SPA 回退顺序、缓存或代理行为变化，也不会把页面源码交给用户。

### D3：截图通过产品 API 映射，而不是暴露数据目录

Markdown 仍保存相对图片链接，保证本地文件结构可读；渲染前根据 `task.screenshot_paths` 的顺序与文件名，将属于当前任务的截图链接改写为：

`/api/v1/tasks/{task_id}/products/screenshot?index={n}`

该端点已有任务归属、索引与安全路径检查，无需把整个 `DATA_ROOT/screenshots` 作为静态目录公开。改写只接受当前任务已登记截图的文件名，外部 HTTP(S) 图片继续交由 DOMPurify 现有安全规则处理。任务详情、单篇笔记和全量笔记浏览页复用同一函数。

新任务登记截图时先 `resolve()` 再转为 `DATA_ROOT` 相对路径，消除数据库中的 `notes/<id>/../../screenshots/...`；前端按 basename 匹配以兼容历史记录。

### D4：超详细长字幕采用“证据 Map → 全局蓝图 → 初稿 → 编辑审校”

当档位为 `exhaustive` 且有效字幕超过分块阈值时：

1. 按字幕条目、时间戳或段落等自然边界切为约 12,000 字符的 source chunk，每个有效字符恰好属于一个 chunk；相邻块可附带少量边界上下文，但不得代替本块正文。
2. 每个 source chunk 调用 LLM 生成结构化语义证据包，而不是直接写最终章节。证据包使用稳定 ID，记录主题、结论、定义、论证链、关键数据、例子、反例、边界、术语、有效问答、时间范围、跨段线索和 ASR 不确定项。若输出有内容但遗漏规定命名空间，允许一次只补结构、不得删改事实的证据 ID 修复；空输出或修复后仍无 ID 则失败。
3. 把全部证据包交给全局规划调用，以严格 JSON 建立课程标题、核心命题、学习目标、全局术语表、概念关系、逻辑 / 教学顺序，以及章节的 `chapter_id`、标题、目的、`evidence_ids` 和 `source_chunks`。术语表综合跨段重复发音和功能上下文，只把高置信音译统一到规范专名，明确区分概念与产品；无法确认的词保留不确定性，不得猜成另一个熟悉品牌。跨多个时间段反复出现的同一主题必须合并；互相矛盾或无法确认的材料必须保留为待辨析项。JSON 语法错误或中途截断时允许一次基于全部证据的结构修复，不能只闭合残缺括号。后端机械验证每个语义证据 ID 至少分配到一个章节；缺失时要求规划调用修复，仍不完整则失败。
4. 按蓝图逐章生成初稿。每章只接收全局主线、该章规划、对应证据包、由 `source_chunks` 定位的完整原始字幕片段、PDF 参考（如有）和截图约束；这样既拥有全局视角，又有足够输出空间展开定义、论证、案例和边界。
5. 每章初稿分别执行编辑审校，审校只处理当前章并接收相同的原始证据和全局术语表，从事实忠实度、证据覆盖、章节内结构、信息价值和可读性五项标准完成终稿章节。审校只能去除无新增信息的重复，不能删除独立的高价值信息，也不能使用外部常识补齐原文；高置信专名必须使用术语表的 canonical 值。若审校后仍检测到已知 ASR 音译、错误年份或概念 / 产品 / 机制归属混淆，额外执行一次实体与术语保真审校；允许在当前章内把直接归错产品的内容移回正确小节，但不得删改正文事实，并以极窄的高置信拼写、年份和产品机制映射兜底。
6. 后端使用蓝图标题、课程主线和学习目标生成文档头部，以蓝图章节标题替换模型可能输出的 `C06` 等内部编号，并按蓝图顺序机械组装所有审校后章节；高置信术语只做确定性拼写归一。禁止对整篇正文再执行全局 LLM 重写，避免编辑器主动压缩已展开章节。
7. 任一证据包、全局蓝图、章节初稿或审校章节为空时任务失败，避免静默交付缺页笔记。终稿还要通过机械结构检查：唯一 H1、有效章节层级、非空正文，以及无内部分析模板或证据 ID 泄漏。若章节内容完整但仅泄漏内部证据编号，允许执行一次不得压缩正文的定向格式清理并重新校验。

“超详细”的内容标准不是输出长度，而是理解和表达质量：读者应能从笔记中理解课程的中心问题、核心结论、概念之间的关系、完整论证、关键案例为何成立、反例与适用边界，以及可以如何实践。字符数、输入输出比仅作为成本 / 性能日志，不进入质量通过条件。

替代方案“提高单次 max_tokens 后一次生成”可以避免截断，但难以稳定解决长课程中的跨段主题合并、证据归属与自我审校；“每块直接写正文再拼接”覆盖较高却产生重复和割裂，因此均不作为 `exhaustive` 的最高质量路径。

### D5：理解、撰写和审校进度回传到现有节点进度

`SimpleProcessor` 接收可选的阶段进度回调，报告 `understand`、`blueprint`、`draft` 和 `review`。运行时分别映射为“正在理解字幕第 n/N 段”“正在构建课程知识结构”“正在撰写第 n/N 章”“正在审校第 n/N 章”，通过既有 `ctx.emit_progress()` 落库和 SSE 推送。回调不进入 LLM provider 适配层。

### D6：验证分层

- 后端单元测试：分块不丢字符、每块形成证据、缺失证据 ID 的无损结构修复、全局蓝图接收并分配全部证据 ID、畸形 / 截断 JSON 修复、证据映射修复、全局术语裁决、每章只接收相关原始片段、逐章审校、可疑音译术语保真、无损格式修复、蓝图标题机械统一、机械组装不再压缩、跨段主题映射、ASR 歧义约束、PDF / 无 PDF 分支、阶段进度、截图路径规范化与产品响应。
- 前端 Node 测试：HTML / JSON 防护、404 未就绪、截图 URL 改写、历史路径兼容、日志字段映射。
- 前端静态检查与构建。
- Docker 重建后，用现有真实任务检查：SRT / 笔记 Tab 不显示 HTML、4 张历史截图可加载、已完成节点能形成活动时间线。

## Risks / Trade-offs

- [超详细模式明显增加 LLM 调用次数、时间和费用] → 仅对长文本 `exhaustive` 启用；UI 显示真实阶段；不自动重跑历史任务。用户已明确选择质量优先。
- [分块证据提取可能遗漏细节] → 初稿和编辑审校继续接收完整原始字幕，证据包用于组织和检查而不是取代原文。
- [全局蓝图可能漏分配证据] → 机械比对证据 ID 与章节映射，缺失时定向修复蓝图，仍不完整则失败。
- [全篇编辑可能压缩独立信息] → 改为逐章深写与逐章审校，最终机械组装，禁止全篇 LLM 重写。
- [多阶段输出可能超过模型上下文或输出上限] → 对每个阶段记录输入规模，使用高上下文模型；任何阶段为空或终稿结构不完整时明确失败，不回退为静默截断。
- [ASR 噪声导致模型过度纠正或混淆概念 / 产品] → 全局蓝图建立带置信度的术语表，逐章写作和审校共同使用；只允许结合跨段上下文做高置信拼写纠正，无法确认的专名、数字和语句以“不确定”标记保留。
- [历史截图路径含 `..`] → 后端仍执行 `resolve()` + `is_safe_path`；前端只按当前任务登记列表映射索引，不直接把数据库路径放进 DOM。
- [SSE 断线期间的逐行日志不可恢复] → 权威节点状态恢复可读活动；完整日志持久化明确留在本 change 的 Non-goals。

## Migration Plan

1. 先部署兼容历史路径的前端 URL 映射和新路径规范化。
2. 部署分层理解、初稿、审校与阶段进度回调；既有任务记录和 Markdown 不迁移。
3. 重建单容器并检查健康端点、任务详情、笔记页和历史截图。
4. 如需回滚，可恢复旧镜像；数据库 schema 未变化，新增 Markdown 与截图路径仍符合现有产品 API。

无。语义证据粒度、阶段输出上限和质量提示先作为 `exhaustive` 内部策略，后续根据真实样本调优，不在本 change 增加新的设置项。
