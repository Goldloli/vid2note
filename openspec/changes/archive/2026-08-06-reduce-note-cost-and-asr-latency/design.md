## Context

现有超详细实现先把 18 万字符字幕切成 4 段提取证据，再生成全局蓝图，随后生成 12 章初稿并逐章完整审校。真实基线中，章节初稿与审校合计占 26 次调用；审校输出长度几乎等于初稿，造成重复输出。最终 54,440 字笔记仍出现重复主题、内部“术语确认/跨段线索”模板和过度表格化。

bcut 侧已有 VAD、线程池、分段 crc32 缓存和退避轮询，但运行配置中的 `asr.config.concurrency=1` 覆盖全局并发 3；`cache_dir` 为空使缓存没有持久落点；142～153 分钟 PCM WAV 约 273～294 MB，120 秒目标产生约 55 段串行上传。基线 149.3 分钟视频的 ASR 为 464 秒。

## Goals / Non-Goals

**Goals:**

- 保留超详细对完整素材的高覆盖、论证关系、案例、边界和术语准确性，同时显著减少重复输入和重复输出。
- 让新长视频的超详细任务在同模型下将调用数、Token、估算费用和笔记耗时相对基线明显降低；质量以结构、覆盖、重复率、内部模板泄漏和人工抽样共同验收。
- 让 bcut 使用真正的多并发、280 秒安全分段和压缩语音上传，并使完全相同音频可在 VAD 前命中整段缓存。
- 为 ASR 冷/热性能提供可持久化、可解释的分段数、输入/上传字节、缓存状态和阶段耗时。

**Non-Goals:**

- 不更换 DeepSeek 模型，不靠截断字幕、隐藏 usage 或固定压缩最终字数达成费用目标。
- 不把 bcut 描述成稳定官方服务；不对服务端排队时间作绝对承诺。
- 不改变简洁、适中、详细档的 ai_srt2md 生成主干。
- 不引入 GPU、说话人分离或新的外部依赖。

## Decisions

### D1：用真实基线而不是理论 Token 估算验收

基线固定记录任务 ID、视频时长、字幕字符/条目、节点起止时间、全部 usage、最终笔记结构和文件。优化后使用时长相差不超过 5% 的另一段 AI 主题视频做冷启动端到端测试；另用相同音频做热缓存测试。不同视频的总量比较只用于工程性能，质量结论同时使用归一化指标和人工抽样，不把内容差异误判成算法收益。

替代方案是只用单元测试或同一任务重跑；前者无法反映远端服务和真实 Token，后者会把缓存收益混入冷启动对比，均不采用。

### D2：用户只保留 `exhaustive` 一个最高详细档

新任务和 UI 不再接受/展示 `thorough`。历史数据库不批量改写；读取和重跑旧 `thorough` 时在运行边界映射为 `exhaustive`，保证历史可访问。`concise`、`balanced`、`detailed` 不变。

### D3：保留证据提取，删除默认逐章全文审校

长字幕仍按自然边界生成详细证据包，避免一次超长蓝图丢失后半段细节。蓝图只做一次全局去重和章节分配；覆盖缺口优先请求紧凑映射补丁，而不是重写整份蓝图。

章节初稿主要消费全局蓝图和被分配的证据包。证据包必须包含足以追溯的原文摘录和 source chunk 标识，因此不再把完整原始 chunk 逐章重复发送。章节输出携带一个可机械剥离的覆盖标记，代码验证证据 ID。

全部初稿完成后只执行一次紧凑全局审计，返回 JSON 问题列表，不返回完整笔记。仅对存在事实、覆盖、重复、术语或结构问题的章节发起局部修复；无问题章节直接进入终稿。最终仍由代码机械组装。

替代方案是把完整字幕一次交给模型直接写终稿，调用最少但对 18 万字符材料的后半段覆盖风险较大；也不采用当前每章全文审校，因为基线证明其输出成本高且大多原样复述。

### D4：质量门禁由确定性规则和一次语义审计共同承担

确定性门禁检查唯一 H1、章节数量、空章节、证据覆盖标记、内部 ID/模板泄漏、标题近重复和异常高表格密度。语义审计只判断跨章重复、事实/术语漂移、重要证据遗漏和论证断裂。修复采用章节 ID 与明确问题列表，不允许模型扩写未被证据支持的维度。

### D5：ASR 使用引擎感知的并发与分段档案

`online_concurrency` 默认 3，仅作用于 bcut/外部在线引擎；`local_concurrency` 固定默认 1。旧 `concurrency` 首次读取时兼容，但保存后迁移为新字段并不再覆盖。bcut 的目标分段默认 280 秒、硬上限 295 秒；Whisper 保持现有更短目标。

线程池仍是有界并发。连续实测最初被误判为并发限流：149 分钟旧策略约消耗 75 次两分钟任务，随后新策略恰有 22 段成功、其余开始 412；公开参考客户端同时声明 12 小时最多 100 次、累计最多 360 分钟，二者高度吻合。因此不以降低并发掩盖滚动额度问题，而是在整项任务开始前持久化预留预计调用数和音频时长。额度不足时，`online_first` 整项改用本地档案，`single` 明确失败并给出恢复时间；运行途中突发 412/429 时立即打开本任务熔断，不做无效重试。

### D6：线上分段使用 MP3，原始 WAV 保留给本地兜底

VAD 仍基于原 WAV 检测静音。仅供在线引擎的临时分段编码为 16 kHz、单声道、64 kbps MP3；本地 Whisper 降级时可从原 WAV 对应时间范围生成 WAV，避免让有损格式影响本地路径。bcut 已支持 MP3，无需增加依赖。

为了把改动风险控制在可测范围，本次保留按切点调用 ffmpeg 的实现但显著减少分段数和上传字节；单 ffmpeg 多输出作为后续可独立优化项，除非实测表明本地切片成为主要瓶颈。

### D7：整段内容缓存位于 VAD 之前

缓存键采用 `sha256(audio bytes + engine + language + cache schema version + 影响结果的配置)`，缓存值为原子写入的 Cue JSON。默认目录为 `${DATA_ROOT}/asr_cache`。命中时跳过 VAD、切片、上传和轮询；未命中时仍使用现有分段缓存支持局部恢复。

crc32 继续可用于分段缓存，但整段缓存使用 sha256 降低跨大文件碰撞风险。缓存损坏时忽略并冷启动重建，不能返回部分字幕。

### D8：连接、轮询和重试按一次远端任务的边界组织

每个线程复用自己的 HTTP Session，不在线程间共享可变 Session；每段仍有独立 `_BcutClient` 任务状态。轮询采用快速起步、最高 4 秒的退避，减少短任务完成后的等待尾延迟。POST 创建任务不做 urllib3 自动重试，避免重复创建；GET/PUT 保留有限网络重试，外层整段任务重试缩减为 1 次，412/429 不立即重试。

### D9：ASR 指标写入节点 product metadata

扩展节点上下文以原子追加 JSON-safe metadata，不改变顶层 `srt_path`。记录 `cache_hit`、`audio_duration_seconds`、`segment_count`、`worker_count`、`source_bytes`、`upload_bytes`、`split_seconds`、`transcribe_seconds`、`total_seconds` 和重试/降级计数。历史节点没有 metadata 时继续正常读取。

## Risks / Trade-offs

- [证据包替代完整原文可能遗漏语境] → 强制证据包含原文摘录和来源段，机械覆盖校验加全局语义审计；真实长视频人工抽样后才确认达标。
- [一次全局审计上下文过长] → 输入只包含蓝图和章节终稿候选，不再附完整字幕；超出模型上下文时按章节组审计并合并紧凑问题列表。
- [MP3 可能造成少量识别退化] → 首选 64 kbps、16 kHz 单声道，并比较字幕条目密度、覆盖时长和人工抽样；异常时可配置回 WAV。
- [bcut 是未承诺 SLA 的公益接口且存在滚动额度] → 默认使用本地持久化 12 小时/100 次/360 分钟预检；412/429 立即熔断，禁止继续批量碰撞接口。
- [整段哈希读取大文件有本地开销] → 流式 sha256，预期远小于在线转录；指标单独记录缓存查找时间。
- [不同视频导致前后质量不可完全等价] → 使用时长/主题接近样本，并补充同一 SRT 的离线生成 A/B 或抽样证据覆盖，不只比较字数。

## Migration Plan

1. 先保留基线任务及产物，不修改其数据。
2. 部署时规范化 `asr.config`：缺少新字段则写入在线并发 3、本地并发 1、在线目标分段 280、缓存启用和数据卷缓存目录；旧字段只用于兼容读取。
3. UI 删除 `thorough`；运行时将历史 `thorough` 映射为 `exhaustive`，确认旧任务详情可读和可重跑。
4. 后端与前端测试通过后重建容器，检查 ASR 状态端点显示新生效值。
5. 运行优化后冷启动任务，再重复相同音频验证热缓存。
6. 回滚时恢复旧容器即可；新增缓存目录可保留且旧版本会忽略，历史任务无需回写。

## Open Questions

- 当前远端滚动窗口已经被多轮真实测试耗尽；纯 bcut 的最终 3-worker 冷启动耗时需在窗口恢复后复核，现阶段不得用混合 Whisper 的 146 秒冒充纯在线成绩。
- 64 kbps MP3 对本样本的专有名词识别是否完全等价，需要字幕抽样后决定是否默认提高到 80 kbps。
- 超详细目标费用不设为硬失败门槛；以相对基线下降和质量不退化为主，积累更多样本后再固化绝对预算。
