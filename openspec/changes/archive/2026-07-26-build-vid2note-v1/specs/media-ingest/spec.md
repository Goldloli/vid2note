## ADDED Requirements

### Requirement: 输入接入与来源识别

系统 MUST 接受两类输入并将其归一化为流水线的「媒体来源」:(1)在线视频链接(YouTube、Bilibili、直链);(2)本地视频文件或本地音频文件上传。来源类型 SHALL 在任务创建时被识别并记录,后续下载/提取步骤 MUST 根据来源类型决定是否跳过。

#### Scenario: 提交 YouTube 链接被识别为在线下载来源

- **WHEN** 用户提交一个 `https://www.youtube.com/watch?v=...` 或 `https://youtu.be/...` 形态的链接作为任务输入
- **THEN** 系统 MUST 将该任务的媒体来源标记为「在线视频」,平台识别为 YouTube,并触发 yt-dlp 下载步骤

#### Scenario: 提交 Bilibili 链接被识别为在线下载来源

- **WHEN** 用户提交一个 `https://www.bilibili.com/video/BV...` 或 `https://b23.tv/...` 形态的链接作为任务输入
- **THEN** 系统 MUST 将该任务的媒体来源标记为「在线视频」,平台识别为 Bilibili,并触发 yt-dlp 下载步骤

#### Scenario: 提交直链被识别为在线下载来源

- **WHEN** 用户提交一个指向音视频资源的 HTTP/HTTPS 直链(非上述平台域名)作为任务输入
- **THEN** 系统 MUST 将该任务的媒体来源标记为「在线视频」,并尝试通过 yt-dlp 下载

#### Scenario: 上传本地视频文件跳过下载直接进入提取

- **WHEN** 用户上传一个本地视频文件(如 `.mp4` / `.mkv` / `.mov` / `.webm`)作为任务输入
- **THEN** 系统 MUST 将媒体来源标记为「本地视频」,跳过 yt-dlp 下载步骤,并把该文件作为视频产物直接送入音频提取步骤

#### Scenario: 上传本地音频文件跳过下载与提取直接作为产物

- **WHEN** 用户上传一个本地音频文件(如 `.mp3` / `.wav` / `.m4a` / `.flac`)作为任务输入
- **THEN** 系统 MUST 将媒体来源标记为「本地音频」,同时跳过下载与音频提取步骤,将该文件直接作为音频产物供后续 ASR 使用

#### Scenario: 无法识别的来源被拒绝并给出原因

- **WHEN** 用户提交一个既非已知平台链接、也非可访问直链、且未附带本地文件的输入(例如纯文本或不支持的协议)
- **THEN** 系统 MUST 拒绝创建任务,并返回明确可读的错误说明「无法识别的媒体来源」,不得进入流水线

### Requirement: 整段视频下载与最高画质

对在线视频来源,系统 MUST 使用 yt-dlp 下载**整段完整视频**(而非片段、试看片段或切片),并 SHALL 选取当前可用的最高画质进行下载。下载得到的视频文件 MUST 作为视频产物落盘。

#### Scenario: 下载整段完整视频而非片段

- **WHEN** 系统对一个时长为 N 分钟的在线视频执行下载
- **THEN** 系统 MUST 产出一段覆盖该视频完整时长的单个视频文件,不得仅下载开头试看片段或某一切片

#### Scenario: 选取最高可用画质进行下载

- **WHEN** 目标视频存在多个画质档位(如 360p / 720p / 1080p 及更高)
- **THEN** 系统 MUST 选择其中可用且可下载的最高画质档位进行下载;若最高画质需要合并独立音视频流,系统 MUST 自动完成合并

#### Scenario: 仅在下载成功后产出视频产物

- **WHEN** yt-dlp 下载流程完整结束且产物文件可读、时长大于零
- **THEN** 系统 MUST 将该文件登记为本任务的视频产物(记录绝对路径、字节大小、来源 URL),并允许进入音频提取步骤

#### Scenario: 本地视频来源不触发下载

- **WHEN** 任务来源为「本地视频」或「本地音频」
- **THEN** 系统 MUST 跳过 yt-dlp 下载步骤,且不得发起任何网络下载请求

### Requirement: Bilibili 登录态携带与画质降级

针对 Bilibili 来源,系统 MUST 支持从设置中读取用户粘贴的 cookie 字段(`SESSDATA` / `bili_jct` / `DedeUserID`)并以登录态下载,以获取高画质;若设置中未提供可用 cookie,系统 SHALL 降级到免登录可下载的最高画质,并 MUST 向用户明确提示当前为免登录画质。

#### Scenario: 设置中提供完整 cookie 时携带登录态下载高画质

- **WHEN** 用户在设置页填写了 Bilibili 的 `SESSDATA` / `bili_jct` / `DedeUserID` 三项,且这些 cookie 有效,系统对一条 Bilibili 视频执行下载
- **THEN** 系统 MUST 将上述 cookie 注入 yt-dlp 的下载请求,并以登录用户身份获取并下载该账号可见的最高画质

#### Scenario: 未提供 cookie 时降级到可下载的最高画质并提示

- **WHEN** 设置中未配置 Bilibili cookie(或三项均为空),系统对一条 Bilibili 视频执行下载
- **THEN** 系统 MUST 以免登录身份下载当前可用的最高画质,并在任务进度/日志中产出一条明确提示「未配置 Bilibili cookie,已降级为免登录画质,如需更高画质请在设置页填写 cookie」

#### Scenario: cookie 缺失关键字段时按免登录降级处理

- **WHEN** 设置中只填写了 `SESSDATA` / `bili_jct` / `DedeUserID` 中的部分字段(例如仅有 `SESSDATA`)
- **THEN** 系统 MUST 视为未提供有效登录态,按免登录降级下载,并提示用户补全三项 cookie 字段

#### Scenario: cookie 已失效时识别为登录态错误并提示

- **WHEN** 设置中填写了三项 cookie,但其值已过期或被平台吊销,导致登录态下载失败或仅返回免登录画质
- **THEN** 系统 MUST 识别该情况,降级为免登录画质继续下载(若仍可下载),并产出明确提示「Bilibili cookie 已失效,请重新粘贴」,不得静默当作无 cookie 处理

#### Scenario: cookie 仅用于 Bilibili 来源不外泄到其他平台

- **WHEN** 系统对一个非 Bilibili 来源(如 YouTube)执行下载
- **THEN** 系统 MUST NOT 将 Bilibili 的 cookie 字段附加到该下载请求中

### Requirement: 音频提取

对存在视频产物的任务,系统 MUST 在下载(或本地视频接入)完成后使用 ffmpeg 从视频中提取音轨,产出的音频文件 MUST 满足后续 ASR 步骤的输入要求(单声道或立体声均可、采样率与容器格式被 ASR 层接受)。本地音频来源 SHALL 跳过提取。

#### Scenario: 从下载的视频中提取音轨

- **WHEN** 一个任务已成功获得视频产物(在线下载完成或本地视频上传就绪)
- **THEN** 系统 MUST 调用 ffmpeg 从该视频提取音轨,产出独立的音频文件并登记为本任务的音频产物

#### Scenario: 提取的音频可被 ASR 步骤消费

- **WHEN** 音频提取步骤完成
- **THEN** 产出的音频文件 MUST 为 ASR 层可读取的格式(如 16kHz / 单声道 WAV,或 ASR 层明确支持的容器),且时长与源视频音轨一致(允许在容差范围内)

#### Scenario: 本地音频来源跳过提取步骤

- **WHEN** 任务来源为「本地音频」(用户直接上传音频文件)
- **THEN** 系统 MUST 跳过音频提取步骤,直接将该上传文件登记为音频产物,且不得调用 ffmpeg

#### Scenario: 视频无音轨或提取失败时报错

- **WHEN** 源视频不含音轨,或 ffmpeg 提取过程返回非零退出码
- **THEN** 系统 MUST 终止提取步骤,产出明确错误「音频提取失败」并附 ffmpeg 错误摘要,不得产出空的或损坏的音频产物

### Requirement: 下载失败处理与重试

下载与提取过程中遇到的失败 MUST 被归类为明确的错误类型(链接无效 / 需登录 / 网络 / 平台风控 / 工具缺失等),并产出人类可读的中文错误信息;系统 MUST 允许对失败任务发起重试,重试 MUST 在干净的临时工作区进行,不得复用上次失败的半成品产物。

#### Scenario: 链接无效时产出明确错误

- **WHEN** 用户提交的链接不存在、已被删除,或 yt-dlp 报告无法解析该 URL
- **THEN** 系统 MUST 将任务标记为失败,错误类型归类为「链接无效」,并返回中文错误信息(说明链接无法访问或视频不存在),允许用户修改链接后重试

#### Scenario: 需登录内容未配置 cookie 时产出明确错误

- **WHEN** 目标视频为 Bilibili 等平台的登录可见内容(如会员专享),且当前未配置有效 cookie 或免登录无法获取
- **THEN** 系统 MUST 将任务标记为失败,错误类型归类为「需登录」,并提示用户前往设置页配置对应平台的 cookie

#### Scenario: 网络错误时产出明确错误并允许重试

- **WHEN** 下载过程中发生网络中断、超时或 DNS 解析失败等可恢复的网络错误
- **THEN** 系统 MUST 将任务标记为失败,错误类型归类为「网络错误」,并在错误信息中保留原始错误要点,允许用户直接对该任务发起重试

#### Scenario: 平台风控或限流时产出明确错误

- **WHEN** 平台返回风控、人机验证或限流(如 yt-dlp 报告需要验证码或触发反爬)
- **THEN** 系统 MUST 将任务标记为失败,错误类型归类为「平台风控」,并提示用户稍后重试或检查 cookie / 网络,不得将风控页面内容当作视频产物落盘

#### Scenario: 外部工具缺失时报错并指引安装

- **WHEN** 容器内未找到 yt-dlp 或 ffmpeg 可执行文件,导致下载/提取无法启动
- **THEN** 系统 MUST 在任务启动早期即失败,错误类型归类为「工具缺失」,并明确指出缺失的是 yt-dlp 还是 ffmpeg

#### Scenario: 失败任务可在干净工作区重试且不残留半成品

- **WHEN** 用户对一个此前下载失败的任务发起重试
- **THEN** 系统 MUST 在新的临时工作区重新执行下载与提取,不得复用或拼接上次失败留下的不完整视频/音频文件;重试成功后产物正常登记,重试再次失败则覆盖式更新错误信息

### Requirement: 产物落盘与保留策略

下载得到的视频与提取得到的音频 MUST 作为产物落盘到该任务的工作目录下,并记录其路径与元信息;二者 MUST 各自遵循独立的保留策略(永久 / 7 天 / 30 天,默认值由设置决定),清理步骤 SHALL 按策略自动删除过期产物。

#### Scenario: 视频与音频产物落盘到任务工作目录

- **WHEN** 下载与提取步骤成功完成
- **THEN** 系统 MUST 将视频文件与音频文件分别写入该任务的工作目录(路径可定位、互不覆盖),并在任务记录中登记二者的绝对路径与字节大小

#### Scenario: 已上传的本地文件按产物同样登记与保留

- **WHEN** 任务来源为本地视频或本地音频上传
- **THEN** 系统 MUST 将该上传文件纳入任务工作目录并作为对应产物登记(视频产物或音频产物),适用与下载产物相同的保留策略

#### Scenario: 视频与音频遵循各自独立的保留策略

- **WHEN** 设置中视频产物保留策略为 7 天、音频产物保留策略为 30 天(或任一其他组合)
- **THEN** 系统 MUST 按各自策略独立判定过期,不得因某一类产物的策略而提前或延后删除另一类产物

#### Scenario: 清理步骤按策略删除过期产物

- **WHEN** 某产物的存在时长超过其保留策略规定的天数(且策略非「永久」),流水线清理步骤执行
- **THEN** 系统 MUST 删除该过期产物文件,并更新任务记录以反映产物已清理;策略为「永久」的产物 MUST NOT 被删除
