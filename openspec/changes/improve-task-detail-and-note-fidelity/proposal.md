## Why

真实长视频任务暴露出三处直接影响可用性的缺口：任务详情把未就绪产物或 HTML 回退页当作正文、SSE 日志字段不一致导致日志区空白、已生成的截图使用磁盘相对路径而无法在浏览器加载。与此同时，现有“超详细”模式会把超过 5 万字符的字幕直接截断；在一条 2 小时 12 分、清洗后约 10.25 万字符的真实 SRT 中，01:03:26 之后的内容未进入笔记生成，最终 1.07 万字符笔记不符合“超详细”的完整覆盖预期。

## What Changes

- 将任务详情从偏技术的“产物源码 + 黑色终端”改为面向普通用户的任务概览：明确当前步骤、下一步、产物是否就绪、可读活动时间线，并保留可按需查看的技术信息。
- 统一 SSE 日志消息字段的消费契约，并从已持久化的节点状态恢复基础活动记录，使中途打开页面时不再是空白。
- 仅在对应产物已登记后请求内容；校验响应状态和内容类型，HTML、JSON 错误页或未就绪响应不得渲染为 SRT / Markdown。
- 为任务内截图提供安全的同源产品 URL 映射；笔记详情与任务详情预览都能显示截图，同时将新任务的截图登记路径规范化为相对 `DATA_ROOT` 的无 `..` 路径。
- 把“超详细”重新定义为理解驱动的高质量深度笔记，而不是字符比例更高的转写：全部字幕先参与分段语义理解，再形成跨分段的全局知识模型、课程主线和章节证据映射。
- 以全局知识模型把每个高价值证据 ID 分配到逻辑章节，并建立可验证的高置信术语表，区分概念、产品和 ASR 音译；每章分别结合对应原始字幕深写并独立审校，最终按蓝图标题机械组装。不得再用一次全局重写压缩全部章节，也不得按字幕分块直接拼接。
- 强化超详细提示词，要求解释“结论是什么、为什么成立、如何论证、例子说明什么、适用边界是什么”，合并跨时段重复主题，保留关键数据、反例、注意事项、术语和有价值问答，并显式标记无法可靠纠正的 ASR 歧义。
- 增加语义证据提取、全局蓝图、初稿、编辑审校、质量门禁、截图路径、产物内容类型和任务详情事件映射的回归测试，并重建 Docker 进行真实页面验证。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `note-generation`: 明确超详细笔记的理解质量标准、分层语义综合与证据驱动审校契约，以及截图产物的可访问路径要求。
- `task-pipeline`: 明确实时日志事件的消息字段与可消费性，并让前端可观察“理解字幕、构建结构、撰写初稿、编辑审校”的笔记生成阶段。
- `web-frontend`: 明确任务详情的产物就绪态、可读活动时间线、非正文响应防护，以及笔记截图的同源渲染行为。

## Impact

- 后端：`SimpleProcessor` 长字幕生成策略、超详细提示词、截图产物登记路径、任务产品 API / SSE 契约与相关测试。
- 前端：任务详情页、Markdown 图片 URL 解析、笔记详情 / 笔记浏览页、双语文案、样式与前端测试。
- 运行影响：仅 `exhaustive` 长字幕会使用多阶段 LLM 理解、撰写与审校，调用次数、生成耗时和费用会增加；用户已明确选择优先保证笔记质量，其他详细程度保持现有单次调用行为。
- 兼容性：现有任务和 Markdown 文件无需迁移；前端图片解析兼容历史上含 `..` 的截图路径。

## Non-goals

- 不引入新的 LLM 厂商、ASR 引擎、OCR / 视觉模型或向量检索。
- 不对既有历史笔记自动重跑或改写；用户需要从“笔记”节点重跑才能获得新的超详细结果。
- 不持久化完整底层进程日志，不新增独立日志数据库；中途进入页面的可读历史由权威节点状态恢复，连接后继续消费实时 SSE。
- 不承诺用字符数机械判定内容质量，也不让模型补写原始 SRT / PDF 中不存在的知识。
- 不改动 ai_srt2md 的 LLM 适配层、SRT 校验、PDF 解析与思维导图内核；继续复用其 prompt 模板、统一 LLM 门面与 Markdown 清洗能力，只改造长文本编排与附加约束。
