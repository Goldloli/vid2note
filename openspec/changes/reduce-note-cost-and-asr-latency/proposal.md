## Why

2026-08-04 的真实长视频基线表明，一段 149.3 分钟视频需要 32 次 LLM 调用、871,820 个 Token、约 ¥0.469，并在笔记节点耗时 677 秒；同时 bcut ASR 因局部并发仍为 1、缓存目录未落地、120 秒小分段和 PCM WAV 上传，冷启动耗时 464 秒。需要在保留“超详细”信息覆盖和可读性的前提下，同时降低费用、调用时延与线上转录时长。

## What Changes

- **BREAKING**：移除用户可见及新任务可选的 `thorough`（比较详细）档，只保留 `exhaustive`（超详细）作为最高详细程度；历史 `thorough` 任务继续可读、重跑时兼容映射到 `exhaustive`。
- 把超详细生成从“多段证据提取 + 每章完整审校重写”改为“全局证据蓝图 + 证据定向分章生成 + 确定性覆盖校验 + 紧凑全局审计 + 按需局部修复”，并禁止内部证据模板、重复章节和无素材依据的机械扩写进入终稿。
- 为超详细链路设置可验证的调用数、Token、费用和质量基线；保留现有逐调用 usage 上报，不以关闭统计掩盖成本。
- bcut 在线策略使用独立在线并发、接近安全上限的长分段和面向语音的压缩上传；本地 Whisper 保持单并发，避免 CPU 争抢。系统在整项任务开始前按 12 小时滚动调用数/音频时长预留公益接口额度，额度不足时整项切换而不是生成 bcut/Whisper 混合字幕。
- 在 VAD 前增加整段音频内容缓存，在分段层保留可恢复缓存；默认缓存目录落在数据卷并纳入配置版本，完全相同输入可直接复用 SRT。
- 减少 ffmpeg 子进程和 HTTP 连接建立次数，优化轮询与可重试边界，并记录分段数、上传字节、缓存命中和各阶段时长用于冷/热性能比较。
- 使用两段时长接近的两小时以上本地视频执行修改前后端到端验收，并额外用相同音频验证热缓存，输出费用、速度和质量对比。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `note-generation`：收敛最高详细档位，修改超详细长字幕的规划、生成、审计、修复和成本/质量验收行为。
- `speech-to-text`：修改在线/本地并发、分段格式、整段缓存、连接复用和性能观测行为。
- `settings-management`：迁移旧 ASR 并发配置并提供缓存、在线分段和在线并发设置的稳定默认值。
- `task-pipeline`：在任务节点产物中持久化可比较的 ASR 性能指标。
- `web-frontend`：移除“比较详细”选项并如实展示优化后的 ASR 配置与缓存状态。

## Impact

- 后端：`SimpleProcessor` 超详细链路、笔记档位校验与兼容映射、bcut 客户端、VAD/ASR pipeline、配置快照、任务节点指标和相关测试。
- 前端：设置页详细程度选项、ASR 页面配置字段与中英文文案、相关单测。
- 数据：新增数据卷内 ASR 缓存目录；旧 `thorough` 历史记录不改写，新任务不再产生该值。
- 外部系统：继续复用 ai_srt2md 的 LLM 门面、SRT 清洗、安全防护和 Markdown 产物约定；继续使用实验性 bcut HTTP 接口，不增加新云服务依赖。

## Non-goals

- 不把“省钱”实现为降低模型档次、截断后半段字幕或关闭 usage 统计。
- 不承诺 bcut 的长期可用性、免费性或固定服务端响应时间。
- 不在本次引入 GPU ASR、说话人分离、语义纠错模型或交互式笔记编辑器。
- 不改造简洁、适中、详细三档的 ai_srt2md 主干；本次新增/改造仅限超详细流水线和线上 ASR 性能路径。
