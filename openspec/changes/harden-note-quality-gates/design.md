## Context

真实长视频样例显示，现有四档已经能稳定产出结构完整的 Markdown，但详细与超详细会把输入中的低置信 ASR 词、数字换算错误、语义重复和课程行政内容一起放大。适中档的信息密度和成本最好，主要缺口是观点归因、不确定实体表达和开头缺少可直接复盘的行动摘要。

当前非超详细主干已经具备“内容地图 → 分批章节 → 确定性结构门禁 → 按策略审计/局部修复”，超详细主干也已经具备分段证据、全局蓝图、逐章写作、全局审计和问题章修复。因此本变更不新增生成阶段，而是在现有地图、蓝图与局部修复路由中加入可靠性和信息密度门禁。约束是不得引入外部事实核验或新依赖，也不得让日常合格任务新增付费调用。

## Goals / Non-Goals

**Goals:**

- 在写作提示词中强制数字/单位原样保真、观点归因和低置信实体显式标注。
- 以本地确定性代码识别高置信的数字换算矛盾、疑似 ASR 连续复读、同词括注、重复章节与低价值行政章节。
- 将确定性问题并入现有问题章修复通道，只重写命中的章节。
- 把详细档从固定全局审计调整为风险审计，并减少证据与写作批次，在保持系统性覆盖的同时降低常规调用数。
- 保持适中档现有证据和批次预算，不增加合格任务调用。

**Non-Goals:**

- 不修改 ASR 引擎、字幕内容或 bcut 策略。
- 不联网核验数字、专名或机构，不自动猜测低置信实体。
- 不新增数据库字段、API、前端设置或第三方依赖。
- 不保证识别所有语义矛盾；确定性门禁只处理可低误报判断的模式，其余交给已有风险审计。

## Decisions

### 1. 复用现有问题章修复通道，不新增质量 LLM 阶段

写作完成后，本地代码为每章生成可靠性问题列表，并与证据遗漏、结构错误和既有审计问题合并。问题只附加到对应章节的现有消息链尾部；无问题章节原样组装。

选择该方案是因为它保持现有缓存前缀和局部修复边界。另一方案是增加一次全篇事实核验，但它会固定增加输入/输出 token，并容易把轻微风格问题放大成多章重写。

### 2. 数字门禁采用“原始证据支持 + 高置信换算关系”两层检查

提示词要求数字、币种、时间单位和比例保持证据原单位；若要换算，必须展示公式且结果一致。本地检查只识别两类高置信问题：同一短语/句子中以“即、相当于、折合、换算”等关系连接但归一化后不一致的费率，以及套餐价格/时长与紧邻折算费率明显不一致。检查结果只触发问题章修复，不在代码中擅自改数字。

选择窄规则是为了控制误报。对全文所有数字进行通用匹配会把不同产品、不同口径的合法数字误判为冲突；引入外部计算或事实服务则超出本地工具边界。

### 3. ASR 门禁区分可机械清理与不可确定修复

完全相同的英文/中文同词括注（如 `vibe coding（vibe coding）`）在组装时机械去重。连续两次以上的二至六字重复片段、已有可疑词表命中和低置信术语不自动替换，而是进入局部修复并要求依据证据改写或标注“ASR 名称不确定”。

这样可安全减少展示噪声，同时避免把正常强调或陌生专名武断映射成常见品牌。

### 4. 蓝图语义去重使用保守的本地相似度门禁

对章节标题、目的、要点及其证据摘要生成规范化字符二元组集合；只有标题/目的或完整语义文本同时达到保守阈值时才判为近重复。命中后，非超详细内容地图沿用一次章节映射补丁；超详细蓝图沿用一次 JSON 修复。常见的引言、总结、下期预告、结束语、个人事务等低价值章节标题也在蓝图解析时拒绝。

不使用向量模型是因为会引入依赖、模型加载和额外成本；不在终稿阶段直接删章，是因为直接删除会破坏证据覆盖。

### 5. 课程相关性在证据提取阶段优先过滤

内容地图和超详细证据提示词明确排除寒暄、关注/加群、下期预告、个人安排、会员通知和纯课程行政信息。只有它们直接构成课程目标、承诺或可执行约束时才可作为证据。蓝图标题门禁是第二道兜底，不替代证据提取。

### 6. 详细档使用 42 条证据、每批 3 章和风险审计

详细档保持 6～8 章与每章深度，但证据从 50 条调整为 42 条，写作从每批 2 章调整为每批 3 章，审计从固定执行调整为仅在确定性问题或关键低置信证据存在时执行。适中档仍为 30 条证据、每批 3 章和风险审计。

按 6～8 章估算，详细档正常写作调用由 3～4 次降为 2～3 次，并在无风险时省去 1 次全局审计；代价是少量 context 级证据不再进入详细档，但仍由超详细覆盖。

## Risks / Trade-offs

- [字符二元组不能发现所有语义重复] → 只把它作为高精度门禁，并保留现有全局审计检查跨章重复。
- [数字规则可能遇到不同产品并列而误报] → 仅检查带显式换算连接词或紧邻套餐关系的局部文本，命中后交由证据约束的 LLM 判断，不直接改值。
- [连续重复可能是演讲者的有意强调] → 不机械删除，只要求局部修复依据证据决定保留、改写或标不确定。
- [详细档证据减少可能降低长尾覆盖] → 保留全部 critical/high，优先删减 context 与等价案例；超详细仍承担全部课程相关证据覆盖。
- [蓝图拒绝低价值章节会触发一次修复调用] → 只在模型违反明确规划约束时触发，正常任务零增量。

## Migration Plan

1. 先以单元测试固定档位预算、提示词约束、数字/ASR 门禁、章节去重和低价值过滤行为。
2. 实现本地质量辅助函数并接入非超详细与超详细的现有 preflight/repair 路由。
3. 更新档位配置与提示词，执行目标测试、后端全量测试、前端测试/构建和 OpenSpec 严格校验。
4. 无数据迁移；新配置只影响之后生成或重跑的笔记，历史 Markdown 保持不变。
5. 回滚时恢复档位参数并移除 preflight 问题注入即可，API 与持久化格式无需回退。
